# IMPERIUM — Accepted Review Decisions

Status: Q01–Q18 recommendations accepted by the user on 2026-09-14, with explicit refinements below. This file retains its original filename for existing links. These decisions supplement IMPERIUM_REQUIREMENTS_v0.3.md and supersede conflicting proposals in the initial planning package. Acceptance settles the product directions; it does not invent numerical budgets, calibration coefficients or provider selections that were never specified.

| ID | Accepted decision | Implementation consequence |
|---|---|---|
| Q01 | Non-destructive correction preview and preservation of original history. | Apply a logged, historically effective baseline correction; preserve already-resolved events and decisions without replay or changed past outcomes. Rebuild affected current projections/summaries with the correction identified; future simulation uses corrected facts. No in-world delivery event. Branch replay is not part of this approval. |
| Q02 | Meetings, discussions and political/diplomatic interactions consume no simulated time. The player's decision phase occurs at a fixed date; time passes when the player ends the turn. | Record interaction/decision state at the current simulated timestamp. Physical execution, production, travel and other elapsed-time effects resolve during the requested advance. No conversation time charge or finite meeting/action-point budget is introduced. Repetition alone must not farm support or new intelligence. “Instant” refers to simulated time, not a promise of zero API processing latency. |
| Q03 | Severity plus player awareness and decision relevance governs interrupts; default severity 4–5. | A hidden event cannot interrupt before the player's government learns of it. Delayed discovery interrupts at detection time when relevant; unrelated foreign crises do not automatically interrupt. |
| Q04 | Normal player access is dossiers/assessments only, including candidate/minister evaluation. These should be generally accurate to compensate for missing body language and other interpersonal cues. | Preserve hidden true traits/objectives, confidence and evidence. Avoid arbitrary misleading dossiers; meaningful deception or uncertainty must have an in-world basis. Generally accurate does not mean omniscient or infallible. Sealed generation remains available; explicit God Mode is separate. |
| Q05 | Calendar-aware requested durations and event-driven sub-day timestamps, with bounded integration steps by subsystem. | Support precise crisis timing without real-time simulation. Choose and document calendar edge cases and operational limits during engineering; no numerical maximum interval was supplied or approved. |
| Q06 | Preserve the world, independently reason for major actors, and use lightweight background evolution for minor actors until gameplay makes them relevant. | No detailed AI cycle for every minor country each turn. Relevance can arise through trade, causal dependencies, wars, diplomacy or events, not just direct player contact. Promote actors with persisted state/history intact; never invent retroactive stock or secret successes on promotion. Benchmark latency/cost before selecting spending limits. |
| Q07 | Important individual political figures plus political blocs. | Preserve faction agendas, coalitions, private intentions and exact seat/vote accounting. Individual seats must be excluded from bloc residual totals to prevent double counting. |
| Q08 | Detailed military inventory/organization with aggregate operational resolution and explicit logistics/losses. | Strategic intent, COAs and release authority remain central; no tactical RTS. Engineering will document and test combat calibration. |
| Q09 | Explicit calibrated macro/sector model plus hard treasury/resource accounting. | Expose model assumptions and preserve exact quantities. Detail follows strategic relevance; calibration is engineering work, not an unresolved choice of product direction. |
| Q10 | Initial scope is Gregorian Earth geography with editable political boundaries; retain adapters for future alternatives. | No initial requirement for fictional planets or non-Gregorian calendars. Historical/divergent/custom nations remain supported within this initial scope. |
| Q11 | Default removal ends the campaign; history remains readable. Campaign-specific continuation must be configured. | Defeat alone does not end play. No automatic God Mode revival or general branching feature is added by this decision. |
| Q12 | Cached shell, optional player-safe snapshots and local discussion drafts; live server confirmation for actions and advances. | No offline hidden-state simulation or executable offline directive queue. Clear account/campaign caches on logout/switch. |
| Q13 | Personal/private first deployment with configurable server credentials and provider-neutral interfaces. | Public billing/BYOK is not initial scope. Actual providers and account credentials are selected during integration; acceptance is not a numerical spending authorization. |
| Q14 | Immutable campaign history, observer-safe normal exports and explicit God Mode full exports. | Define backup/restore and retention targets before release; do not claim unspecified recovery guarantees already exist. |
| Q15 | Begin Reign creates World State v1 and the initial Turn 1 briefing without advancing time; one advance ID per requested interval with resumable segments. | Player ends the decision phase to request elapsed time. An emergency pauses that advance; explicit resume continues its remaining interval. UI numbering and job IDs must be distinguished. |
| Q16 | Choose historical/map sources through quality and licensing review; support manual imports and honest provenance. | Engineering selects compatible sources and supported coverage; generated estimates are labeled assumptions and cannot overwrite campaign truth. |
| Q17 | Normal causal views use observer evidence and labeled hypotheses; true causal graph only in God Mode. | Do not reveal secret motives through thread titles, archive edges or summaries. |
| Q18 | Commanders may adapt within approved scope; otherwise return a pending authorization or failed order with a known-fact explanation. | Significant changes require a new in-game authorization. Never silently escalate a conflict or exceed an approved COA. |

## Engineering follow-through

Accepted recommendations also include one canonical Postgres database, private truth and observer projections, durable Cloudflare orchestration, idempotent checkpoints, deterministic versioned rules, provider adapters, exact quantities, scoped retrieval and original-event preservation.

The remaining tasks are validation and specification of engineering details: measured performance/cost envelopes, model/provider selection, calibration coefficients, source coverage/licensing, runtime compatibility, backup targets and request limits. They do not reopen the accepted gameplay choices or require the user to choose routine libraries.

No application code or cloud resources are created by this review update. The original stop-before-full-implementation boundary remains in place.
